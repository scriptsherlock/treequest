Teacher notes
Objective. Pupils can explain that a computer classifies things by asking a short chain of yes-or-no questions, and that the questions are chosen by counting rather than by knowing anything about the subject.
Why this framing. "Fits in a car" is a threshold question, really "is it smaller than roughly this big". Numeric thresholds are what real decision trees split on, so this is not an analogy for the algorithm. It is the algorithm, with the arithmetic made countable.
Being straight about the maths. Splits are scored by misclassification impurity: how many are left in the wrong pile. This is a genuine criterion, but production implementations use Gini or entropy, which respond more smoothly to changes that do not flip the majority class. The principle taught is unchanged.
The engineered surprise. Six animals exist solely so that no single question solves the problem, and the third question is rejected outright.
Checking understanding. Ask why "Is it an elephant?" would be a poor first question. A child who says it sorts out one animal and leaves everything else muddled has understood information gain without meeting the term.
Support. Run page 7 with paper cards and two hoops on a table. Count the odd ones out by hand before touching a screen.
Stretch. Add an animal that breaks the tree (heavy, short, and it somehow does fit) and ask what fourth question would be needed. This is how real models get extended when they meet data they were not built for.
The question a sharp adult will ask. If this works so well, why isn't image recognition done with decision trees? Because a child can name "pointy ears" but cannot say which pixels make them pointy. Decision trees need features handed to them already measured. For images, the features have to be learned — which is what neural networks are for.
