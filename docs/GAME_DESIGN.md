# Game design

The player is a Treekeeper: explore, observe, teach the Wise Tree, receive its chosen gear, and test the prediction in battle. plan.md and quest-data.js are authoritative. This specifies future implementation; no new gameplay ships in this planning pass.

## First slice

Ava or Max enters one compact Village Square/Forest Trail area. An Ancient Grove landmark represents the Wise Tree; a scout interaction opens the journal. One visible existing fire/rock monster can be inspected. Approaching shows a prompt; only E, Enter on a focused prompt, or Engage begins the encounter. Passing nearby never starts combat.

Inspect clues → consult labelled notes → choose a real first-level split → follow the actual prediction path → open the enchanted chest → automatically equip predicted gear → short existing-rule combat → explanation → return to the exact stored position. Retreat/cancel remain available before resolution. Wrong gear remains wrong; mechanical reflexes cannot override classification.

Keep selected equipment and its exact questions/answers visible. A miss offers return-to-tuning; success is acknowledged rather than replaced by a scripted teaching failure.

Keep these names in learning data. Geographical names in WORLD_DESIGN describe locations, not silent dataset renames. Five-level expansion waits for first-slice acceptance.

## Teaching surface

Give the tree most teaching space. Show a few candidate questions, readable Yes/No branches and gear leaves. Put supporting notes in a bounded journal or expandable drawer. Values/labels remain text-accessible; optional Gini/depth details use progressive disclosure. Do not claim typed questions work without recorded measurements.

Preserve three hearts and existing monster/boss rules. Failure leads to a useful debrief/retreat without deleting learning progress. Reward balance remains the baseline until separately evaluated.
